StreamProbe, field by field

Group streaming.allan-nava.github.io, version v1alpha1, kind StreamProbe, namespaced, short name sp. The API is alpha: fields may still change before v1.

spec

FieldTypeDefaultMeaning
urlstring, requiredThe HLS playlist: a media playlist, or a multivariant one (its first variant is followed). Must start with http:// or https://; at most 2048 characters.
intervalduration30sHow often the stream is checked. Values under 5s are raised to 5s.
timeoutduration10sBounds one whole check: playlist, variant and segment.
staleAfterdurationthree target durationsHow long the live edge may stand still before the stream is Stale. Without a target duration in the playlist: three intervals.
checkSegmentbooltrueAsk the origin for the live-edge segment on every check (first 1 KB only).
headersFrom.secretNamestringA Secret in the StreamProbe's namespace whose keys are request header names and whose values are their values (e.g. Authorization: Bearer …), for an origin behind a token. Read at every check, so a rotated token is used from the next one. Missing, empty, a key that is not a header name or a value with a line break: Ready=False, reason InvalidConfig, and the stream is not contacted.
headersFrom.allHostsboolfalseSend the headers to every host the check reaches. Off, they go only to the url's host, so the token does not leak to a CDN serving the variants or segments.
variantsFirst or AllFirstWhich variants of a multivariant playlist are checked. First: the first listed. All: every variant, each with a line in status.variants; Ready is the worst of them, and its message names the variant and counts the live ones. On a media playlist both mean the URL.

status

FieldMeaning
conditionsThe Ready condition (see below).
observedGenerationThe spec generation this status was written for.
lastCheckTimeWhen the stream was last checked.
lastAdvanceTimeWhen the live edge was last seen moving.
liveEdgeSequence number of the last segment: mediaSequence + segments − 1.
mediaSequence#EXT-X-MEDIA-SEQUENCE at the last good check.
targetDurationSeconds#EXT-X-TARGETDURATION at the last good check.
playlistURLThe media playlist actually read: url, or its first variant.
playlistLatencyMillisecondsTime to fetch that playlist.
segmentStatusHTTP status of the live-edge segment; 0 when not checked or no answer.
consecutiveFailuresChecks in a row that could not read the playlist; 0 after a good one.
lastErrorThe error of the last failed check; empty after a good one.
variantsWith spec.variants: All, one line per variant: uri, bandwidth, resolution, reason, message, liveEdge, lastAdvanceTime. The other status fields describe the first variant.

The Ready condition

Tried in this order; the first that applies sets the reason. An event (Normal for Live, Warning otherwise) is recorded when the reason changes.

ReasonStatusWhen
FetchFailedFalseThe playlist could not be fetched (network, non-200) or parsed, a multivariant playlist had no variant, or the media playlist lists no segment.
EndedFalseThe playlist has #EXT-X-ENDLIST.
StaleFalseThe live edge has not moved for longer than staleAfter.
SegmentFailedFalseThe live-edge segment answered outside 2xx, or not at all.
LiveTrueOtherwise.
InvalidConfigFalseThe probe cannot be made as configured: its headersFrom Secret is missing, unreadable or invalid. Checked before anything else; the stream is not contacted.
 
kubectl wait --for=condition=Ready sp/unified-live-demo --timeout=2m
kubectl get sp -o custom-columns=NAME:.metadata.name,REASON:.status.conditions[0].reason,EDGE:.status.liveEdge

On the manager's metrics endpoint, next to controller-runtime's own. Labels namespace and name; the series of a deleted probe are dropped.

Alerts

With the Prometheus Operator in the cluster, --set prometheus.enabled=true on the chart adds a ServiceMonitor and a PrometheusRule. The rules live in dist/chart/files/streamprobe.rules.yaml and have unit tests (promtool test rules test/prometheus/rules_test.yaml).

AlertExpressionFor
StreamNotLivestreamprobe_ready == 05m
StreamPlaylistSlowp95 of streamprobe_playlist_fetch_seconds over 10m > 1s10m
StreamprobeDownup of the operator's metrics service == 05m

If your Prometheus selects rules by a label (with kube-prometheus-stack, release), set it with prometheus.labels.

Grafana dashboard

The chart carries a dashboard, dist/chart/files/streamprobe-dashboard.json: live and not live streams, a live/not-live timeline per stream, seconds since the live edge moved, playlist fetch time (p50 and p95), segments per minute, checks by verdict, with filters for namespace and stream. With --set grafana.dashboard.enabled=true it becomes a ConfigMap labelled grafana_dashboard: "1", which Grafana's dashboard sidecar loads (kube-prometheus-stack has one); grafana.dashboard.namespace and .annotations cover a sidecar that watches one namespace or files dashboards in folders. Without the sidecar, import the JSON in Grafana and pick your Prometheus data source.

Install, run, remove

From a clone of the repository, against the cluster of your current kubectl context:

make install                      # the CRD
make run                          # the controller on this machine (Ctrl+C to stop)

make deploy                       # the controller in the cluster, from the published image
make deploy IMG=ghcr.io/allan-nava/streamprobe-operator:0.1.0   # a release instead of :main

kubectl apply -k config/samples   # the example StreamProbe

make undeploy                     # remove the controller
make uninstall                    # remove the CRD, and with it every StreamProbe

The image is ghcr.io/allan-nava/streamprobe-operator, for linux/amd64 and linux/arm64: :main and :sha-<commit> follow the main branch, :X.Y.Z, :X.Y and :latest the releases. Each release also attaches install.yaml, the whole install pinned to its image:

kubectl apply -f https://github.com/Allan-Nava/streamprobe-operator/releases/latest/download/install.yaml

With Helm, from the chart published with each release (same version as the image):

helm install streamprobe-operator oci://ghcr.io/allan-nava/charts/streamprobe-operator \
  --version <X.Y.Z> --namespace streamprobe-system --create-namespace

For development: make test (unit tests and envtest, no Docker), make lint, make manifests generate after changing the markers, make test-e2e on kind.
